# 参考资料：API 密钥申请指南（零基础版）

> 本文件指导用户从零申请 YouTube Data API v3 密钥，并明确密钥文件的存放位置。
> 目标用户：没有任何技术背景，第一次听说"API key"的人。

## 一、先理解两件事（30 秒版）

1. **API key 是什么**：它是一串类似 `AIza...` 的密码，代表"你本人"向 YouTube 官方申请数据。没有它，YouTube 不给数据。
2. **本流程只用它读公开信息**：搜索公开视频、读取公开评论。不发评论、不登录任何人的账号、不采集评论者身份信息。这是合法合规的公开数据采集。

## 二、申请 YouTube Data API v3 密钥（约 10 分钟）

1. 打开 Google Cloud Console：<https://console.cloud.google.com/>
   - 用任意 Google/Gmail 账号登录（没有就先注册一个，免费）。
2. **创建项目**：点击页面顶部左上角的项目下拉框 → "新建项目" → 项目名随意（如 `my-research`）→ "创建"。等待约 30 秒，创建后在下拉框里选中它。
3. **启用 API**：左上角菜单 ☰ → "API 和服务" → "库" → 搜索框输入 `YouTube Data API v3` → 点进去 → 点蓝色按钮"启用"。
4. **创建密钥**：☰ → "API 和服务" → "凭据" → 顶部"+ 创建凭据" → 选"API 密钥"。屏幕上弹出密钥，形如 `AIzaSy...`（39 个字符左右）。
5. **限制密钥（重要，防盗用）**：在刚生成的密钥行点"限制密钥"：
   - "API 限制"选"限制密钥"→ 下拉勾选 **YouTube Data API v3** → 保存；
   - 其余选项保持默认即可。
6. 需要时复制密钥；Google 随时允许在凭据页重新查看。

> 免费配额：每天 10,000 个单位。搜索一次约花 100 单位，读评论一次约 1 单位。
> 一次调研（30 个视频 × 1000 条评论）通常几百到几千单位，远低于上限。

## 三、密钥文件存放在哪里（硬性规定）

存放在**项目文件夹根目录**，文件名为 `youtube_api_key.txt`：

```text
<你的项目文件夹>/youtube_api_key.txt
```

**硬性要求：必须和采集脚本 `pachong.py` 放在同一个文件夹里。** 判断方法很简单——在文件夹里同时看到这两个文件，就是对的：

```text
<你的项目文件夹>\
├── pachong.py             ← 采集脚本
└── youtube_api_key.txt    ← 密钥文件（两者必须同级）
```

脚本启动时会自动在**自己所在的文件夹**里找这个文件。所以把密钥文件放到子文件夹、桌面或别的盘，都会导致 `Missing API key` 报错。

创建方法（任选其一）：

- 用记事本：新建文本文件 → 把密钥**单独一行**粘进去 → 另存为，文件名填 `youtube_api_key.txt`，保存类型选"所有文件"，编码选 UTF-8 → 保存到上述文件夹。
- 在对话中操作时：由 WorkBuddy 用文件工具创建该文件并写入用户提供的一行密钥。

文件内容示例（仅一行，无引号、无空格、无其他文字）：

```text
AIzaSyABCDEFG1234567890abcdefghijklmnopq
```

## 四、密钥安全红线（必须遵守）

1. **不要把密钥发到聊天窗口、微信群、邮件**里。若已在对话中口头提供，WorkBuddy 写入文件后应提醒用户：该 key 已出现在对话记录中，建议用完后去 Google Cloud Console 删除并重新生成。
2. **不要把密钥写进 `pachong.py`** 或任何会提交 Git 的代码文件。
3. `youtube_api_key.txt` 已在 `.gitignore` 中排除，不会被误提交；但不要手动把内容复制到别处。
4. 怀疑泄露时的处理：Google Cloud Console → 凭据 → 删除该密钥 → 按第二节重新申请一把 → 更新 `youtube_api_key.txt`。
5. 换电脑/换环境：把 `youtube_api_key.txt` 单独拷贝即可，不要在聊天里转发内容。

## 五、换用其他数据源时

本流程默认 YouTube。若用户的数据源是其他平台（B 站、微博、RSS 等），规则相同：

- 文件存项目文件夹根目录，命名 `<来源名>_api_key.txt`（如 `bilibili_api_key.txt`）；
- 同样只读公开数据、只存一行密钥、不进聊天和 Git；
- 具体的申请入口把第二节替换成对应平台的开放平台文档即可，其余流程（Step 2～6）完全不变。

## 六、配置是否成功的自检

在项目文件夹、环境激活状态下执行：

```bash
conda activate dhr
cd /d <你的项目文件夹>
python pachong.py --topic <你的主题slug> --dry-run
```

- 没有提示 `Missing API key` → 密钥文件路径和内容正确；
- 能跑完并生成 `candidates.csv` → 密钥有效、网络通畅、API 已启用；
- 若提示 `quotaExceeded` / HTTP 403 → 见排查表（`troubleshooting-checklist.md`），通常是日配额用尽或密钥未限制到正确 API。
